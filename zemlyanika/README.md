# «Земляника» — механизм инкапсуляции ключа на решётках

Реализация по проекту методических рекомендаций ТК 26 (далее — МР) на
собственном «Стрибоге» из [`gost/`](../gost): H — «Стрибог-256», G —
«Стрибог-512», а генератор псевдослучайных последовательностей по
Р 1323565.1.006-2017 написан сам поверх «Стрибога-512». Сторонних
криптографических библиотек нет. По устройству схема близка к Kyber /
ML-KEM: шифрование Zemlyanika.PKE на задаче module-LWE и надстройка
Zemlyanika.KEM с перешифрованием и неявным отказом.

Реализовано всё из МР: строки и кольцо R_q (раздел 5), генератор R006-2017,
MatrixGen, CBD, кодирование многочленов (раздел 7), PKE и KEM (разделы 7.5,
8) для четырёх наборов параметров таблицы 1: Z512, Z768-R, Z768-C, Z1024.

## Требования и запуск

- **Python 3.10 или новее** (проверено на 3.14.8).
- **Зависимости:** для реализации — только стандартная библиотека и
  `gost/`; для тестов — `pytest` (`requirements.txt` в корне).

Из корня репозитория:

```bash
python -m pytest zemlyanika/tests -v
python -m zemlyanika.examples
```

Тестов 47, около 2 с. `examples` печатает по каждой проверке ожидаемое,
полученное и PASS/FAIL; итог `PASS 22, FAIL 2 из 24` — оба FAIL в размере
закрытого ключа, где таблица 1 расходится с алгоритмом 5.

## Использование

```python
from zemlyanika import kem
from zemlyanika.params import Z768_C

pk, sk = kem.keygen(Z768_C)
key, c = kem.encaps(Z768_C, pk)        # key — 32 байта
assert kem.decaps(Z768_C, sk, c) == key
```

Время на Python 3.14, Apple M5: от 7 до 30 мс на каждую операцию, в
зависимости от набора.

## Отступления от буквального текста

В трёх алгоритмах МР опечатки: программа, написанная по ним дословно, не
работает. Сама схема верная, и с исправлениями реализация работает на всех
четырёх наборах. Тесты показывают, что именно ломается без исправления
(для алгоритма 6: MatrixGen отвергает буфер из 256 бит seed_A). Подробно — в [`ANALYSIS.md`](ANALYSIS.md).

- **Алгоритм 10, шаг 5.** «если c′ = c тогда K′ := K̃» — условие
  перевёрнуто: при буквальном прочтении на правильном шифртексте
  возвращается ключ отказа. Взято c′ ≠ c.
- **Алгоритм 6, шаг 1.** В MatrixGen подаются 256 бит seed_A вместо
  R006-2017(seed_A, 256·k²·t), как в KeyGen; вектор b не извлекается из pk.
  Взято R006-2017(seed_A, …), b декодируется из pk.
- **Алгоритм 5, шаг 6.** s = CBD(η_e, …), хотя буфер и Dec рассчитаны на
  η_s. Взято η_s; иначе для Z768-C и Z1024 расшифрование не работает (в Z512 и
  Z768-R η_s = η_e, и ошибка не видна).

## Принятые трактовки

- **Строки и векторы.** Двоичная строка b — это вектор с zᵢ = b[i], то есть
  число bits_to_int(b). Начальное заполнение генератора K = bits_to_int(seed),
  его выход R даёт строку buf с buf[i] = i-му разряду R.
- **«Стрибог» в генераторе.** Вектор U ∈ V₅₀₄ подаётся в ГОСТ 34.11 как
  вектор; байтовая строка для `gost.streebog` — в порядке RFC 6986 (младший
  байт первым). Реализация в пакете `gostcrypto` записывает U в обратном
  порядке байтов и даёт для того же seed другую последовательность; документ
  не позволяет выбрать между ними.
- **H и G.** На вход подаются байтовые строки (pk, c, байты строк m, Z) в
  порядке RFC 6986. K — первые 32 байта выхода G, rnd — последние 32.

## Что проверено

| Что | Наборы | Результат |
|---|---|---|
| \|pk\| и \|ct\| по таблице 1 | все четыре | совпадают |
| \|sk\| по таблице 1 | Z512, Z768-R | совпадает |
| \|sk\| по таблице 1 | Z768-C, Z1024 | **не совпадает**: 1536 и 2016 байт по алгоритму 5 против 1440 и 1888 в таблице |
| Decaps возвращает K из Encaps | все четыре | да |
| неявный отказ при изменённом шифртексте: H(Z ‖ c) | все четыре | да |
| частота ошибок расшифрования | все четыре | 0 из 2000 попыток на набор (ниже ≈ 1,5·10⁻³) |
| пик памяти KeyGen, Encaps, Decaps | все четыре | от 108 до 318 КиБ, тест требует меньше 1 МиБ; повторные вызовы память не копят |

Кроме того, тесты проверяют:
- быстрое умножение против формулы (12) и x²⁵⁶ = −1;
- ошибку Compress/Decompress не больше полушага;
- кодирование и декодирование;
- порядок чтения бит в MatrixGen;
- распределение CBD;
- то, что генератор при меньшей длине даёт начало той же последовательности;
- крайние сообщения (все нули, все единицы);
- отказ на неверных длинах и параметрах.

## Ограничения

- Совпадение с документом проверить нельзя: контрольных примеров в МР нет.
- Нет защиты от атак по времени, кроме сравнения c′ и c за постоянное время
  (`hmac.compare_digest` из стандартной библиотеки).
