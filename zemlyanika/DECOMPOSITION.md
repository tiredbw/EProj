# Декомпозиция алгоритма «Земляника» на составляющие

Настоящий раздел выделяет из текста проекта методических рекомендаций
алгоритмы, подлежащие программной реализации, и указывает их входные/
выходные данные и последовательность выполнения.

«Земляника» — постквантовый **механизм инкапсуляции ключа** на основе
решёточной задачи (module-LWE, по образцу Kyber/ML-KEM), построенный
поверх собственной системы асимметричного шифрования Zemlyanika.PKE.

## 1. Математический фундамент (раздел 5)

Уровни абстракции, каждый следующий опирается на предыдущий:

| Уровень | Что определяет | Раздел |
|---|---|---|
| Двоичные/байтовые строки | `bits_to_int`, `int_to_bits`, `bytes_to_bits`, `bits_to_bytes` | 5.1 |
| Кольцо Z_q | сложение/умножение по модулю q = 2^t | 5.2 |
| Кольцо многочленов R_q = Z_q[x]/(x²⁵⁶+1) | сложение, умножение многочленов (формула свёртки) | 5.3 |
| Двоичные многочлены | представление открытого текста (256 бит) как многочлена с коэффициентами {0,1} | 5.4 |
| Векторы/матрицы из многочленов | операции над R_q^k и R_q^(k×k) (k — параметр схемы) | 5.5 |
| Биномиальное распределение B_η | распределение коэффициентов секретного вектора и шума | 5.6 |
| Функции сжатия/восстановления | `Compress_d`/`Decompress_d` — уменьшение размера шифртекста за счёт потери точности | 5.7 |

## 2. Внешние криптопримитивы

Хэш-функция Стрибог (ГОСТ 34.11-2018, варианты на 256 и 512 бит) и
механизм выработки псевдослучайных последовательностей по
Р 1323565.1.006-2017 (раздел 7.1) — не являются предметом реализации по
заданию, документ использует их как готовые строительные блоки.

## 3. Вспомогательные алгоритмы (раздел 7)

| Алгоритм | Назначение | Вход | Выход | Раздел |
|---|---|---|---|---|
| `MatrixGen` | случайная равновероятная выборка публичной матрицы A из R_q^(k×k) | псевдослучайная строка длины 256·k²·t бит | матрица A | 7.2 |
| `CBD` | выработка секретного вектора / вектора шума с коэффициентами, распределёнными по B_η | η, число многочленов l, псевдослучайная строка | l многочленов из R_q | 7.3 |
| `encode`/`decode` | перевод многочлена из R_p в байтовую строку и обратно | многочлен + длина представления коэффициента s | байтовая строка ↔ многочлен | 7.4 |

## 4. Система асимметричного шифрования Zemlyanika.PKE (раздел 7.5)

Базовый примитив, на котором строится KEM — классическая LWE-схема
шифрования (структурно аналог Kyber.PKE):

- **KeyGen**: выработать `A` через `MatrixGen`, секретный вектор `s` и
  шум `e` через `CBD`, открытый ключ `b = A·s + e`.
- **Enc(pk, m, rnd)**: выработать свежие `r`, `e1`, `e2` из `rnd`;
  зашифровать как `u = Aᵀ·r + e1`, `v = bᵀ·r + e2 + (q/2)·m`; сжать `u`,
  `v` функциями `Compress` перед кодированием в байты.
- **Dec(sk, c)**: восстановить `m' = v'' − sᵀ·u''` после `Decompress`;
  округлить каждый коэффициент к ближайшему биту (порог `q/4 < m'ᵢ ≤ 3q/4`).

## 5. Механизм инкапсуляции ключа Zemlyanika.KEM (раздел 8)

Надстройка над Zemlyanika.PKE по схеме Fujisaki–Okamoto (неявный отказ
через случайную строку `z` на случай ошибки декапсуляции).

### 5.1 KeyGen

**Вход:** нет (использует только параметры схемы).
**Выход:** `pk` (открытый ключ PKE), `sk = sk' ‖ pk ‖ H(pk) ‖ Z`.

Последовательность: сгенерировать пару ключей PKE; добавить к закрытому
ключу копию открытого ключа, его хэш и случайную 256-битную строку `z`
(используется только при неудачной декапсуляции — не раскрывает
информацию об ошибке через длину/содержимое вывода).

### 5.2 Encaps

**Вход:** открытый ключ `pk`.
**Выход:** общий секретный ключ `K` (32 байта), шифртекст `c`.

Последовательность: выбрать случайное сообщение `m`; вычислить
`K ‖ rnd = G(m ‖ H(pk))`; зашифровать `m` как `c = PKE.Enc(pk, m, rnd)`.

### 5.3 Decaps

**Вход:** закрытый ключ `sk`, шифртекст `c`.
**Выход:** тот же общий секретный ключ `K`, что вычислен в Encaps (при
корректном `c`), либо псевдослучайный ключ на основе `Z` (при ошибке).

Последовательность: расшифровать `m' = PKE.Dec(sk', c)`; пересчитать
`K' ‖ r' = G(m' ‖ h)`; зашифровать заново `c' = PKE.Enc(pk, m', r')` и
сравнить с полученным `c`. При совпадении вернуть `K'`, иначе — ключ
`K̃ = H(Z ‖ c)`, вычисленный независимо от результата расшифрования —
это защита от атак через различие в обработке валидного/невалидного
шифртекста (неявный отказ).

## 7. Особенности, на которые стоит обратить внимание при реализации

- **Документ сам отмечает, что является предварительной редакцией**
  («Не рекомендуется использование настоящей редакции документа в
  реальной эксплуатации») — в отличие от Кодиеума и Гиперикума, здесь
  нет приложения с контрольными примерами вообще, проверка возможна
  только через самосогласованность протокола.
- Четыре переменных параметра (`q, k, η_s, η_e, d_u, d_v`) задают баланс
  между размером ключей/шифртекста, стойкостью и вероятностью ошибки
  расшифрования (decryption failure rate) — в документе явно не указаны
  рекомендованные наборы значений (в отличие от Кодиеума и Гиперикума, у
  которых есть таблицы наборов параметров) — их нужно выбрать
  самостоятельно, аргументированно, с указанием обоснования в отчёте.
