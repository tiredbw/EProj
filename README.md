# EProj: постквантовые алгоритмы МР ТК 26 на Python

**Тема.** Реализация постквантовых алгоритмов, описанных в проектах
методических рекомендаций (МР) Технического комитета 26, на языке Python,
проверка соответствия реализации документу и подготовка предложений по
улучшению качества проекта.

**Команда:** Авилов Алексей, Козлов Дмитрий, Гулиева Юлия, группа АВТ-551.

| Папка | Что внутри | Документ |
|---|---|---|
| [`gost/`](gost/) | собственные «Стрибог» (ГОСТ 34.11-2018), «Кузнечик» (ГОСТ 34.12-2018), HMAC и KDF_TREE (Р 50.1.113-2016) | стандарты, RFC 7836 |
| [`kodieum/`](kodieum/) | механизм инкапсуляции ключа «Кодиеум» на кодах Гоппы: 3 набора, все режимы | `Кодиеум_МР.pdf` |
| [`giperikum/`](giperikum/) | схема подписи «Гиперикум» на хэш-функциях: 6 наборов | `Гиперикум_МР.pdf` |
| [`zemlyanika/`](zemlyanika/) | механизм инкапсуляции ключа «Земляника» на решётках: 4 набора | `Земляника_МР.pdf` |

Все три варианта построены только на собственных «Стрибоге» и «Кузнечике»
из `gost/`, без сторонних криптографических библиотек.

## Запуск

**Версия Python: 3.14.8.** На ней собран Docker-образ и сделаны все замеры.
Проверено и на Python 3.10.22; нужна версия 3.10 или новее. Все команды —
из корня репозитория. Для контрольных примеров править код не нужно:
ожидаемые значения читаются из файлов, начальные значения заданы.

```bash
pip install -r requirements.txt
python main.py
python -m pytest
```

**`python main.py`** по очереди прогоняет контрольные примеры всех частей
(около 15 с) и печатает сводку:

```
СВОДКА
  «Стрибог» и «Кузнечик»: совпало со стандартом 25 из 25 значений
  «Кодиеум»: PASS 31, FAIL 5 из 36 проверок
  «Гиперикум»: PASS 71, FAIL 1 из 72 проверок
  «Земляника»: PASS 22, FAIL 2 из 24 проверок
```

С флагом `--full` «Гиперикум» строит полные подписи наборов «Б»: PASS 153,
FAIL 2 из 155 (несколько минут). Каждый FAIL объяснён:

- «Кодиеум» — пять выходов KDF в шаге 2 примеров Б.3 и Б.5. Наша KDF
  совпадает с примерами RFC 7836, а значения документа не получаются ни при
  одном из перебранных соглашений. Все следующие шаги сходятся;
- «Гиперикум» — опечатки документа: idx_tree в A.5 и хвост слоя 0 в A.6.
  Верные значения подтверждены пересчётом;
- «Земляника» — размер закрытого ключа Z768-C и Z1024 в таблице 1
  расходится с алгоритмом 5 самого документа.

**`python -m pytest`** прогоняет все тесты, около полутора минут. Ожидаемый
итог: `269 passed, 5 skipped, 2 xfailed`.
- 2 xfailed — те же шаги KDF «Кодиеума»;
- 5 skipped — долгие тесты «Гиперикума». Они запускаются командой
  `GIPERIKUM_SLOW=1 python -m pytest giperikum/tests` и идут несколько минут;
- если пакет `gostcrypto` не установлен, пропускаются ещё 15 сверочных
  тестов `gost/`.

Другие команды:

```bash
python -m pytest -k memory     # только 14 тестов по памяти
python -m gost.examples        # каждое контрольное значение: ожидаемое, полученное, PASS/FAIL
python -m kodieum.examples
python -m giperikum.examples   # --full — с полными подписями
python -m zemlyanika.examples
python measure.py              # время и пик памяти каждой операции; --full — все наборы (около 30 мин)
python compare_kem.py          # «Кодиеум» и «Земляника» на одинаковых входах; --full — три уровня
```

**Docker**, без установки Python:

```bash
docker build -t eproj .
docker run --rm eproj
docker run --rm eproj python -m pytest
```

**PyCharm.** В `.idea/runConfigurations/` лежат готовые конфигурации:
- «Все тесты» и «Тесты по памяти»;
- «Все примеры (main.py)»;
- тесты и примеры каждой части;
- «Память и время (measure.py)»;
- «Сравнение Кодиеум и Земляника».

## Ответы на два главных вопроса задания

**1. Можно ли по одному только проекту создать однозначную и
воспроизводимую реализацию?** Нет, только с опорой на контрольные примеры.
Математика во всех трёх документах описана в целом хорошо, но:
- не определено, как данные превращаются в байты на входе «Стрибога» и
  «Кузнечика»: в «Кодиеуме» и «Гиперикуме» это пришлось подбирать по
  примерам, а у «Земляники» примеров нет совсем;
- опечатки в формулах и псевдокоде приходится находить и исправлять самим.

**2. Какие изменения облегчили бы независимую реализацию?**
- нормативный раздел «Представление данных»;
- полные контрольные примеры для всех наборов, режимов и пути отказа;
- примеры, полученные эталонной программой, и псевдокод, проверенный
  исполнением;
- полный список ограничений на параметры и правила для неверных входов;
- единые обозначения.
