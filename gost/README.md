# Этап 1 — собственная реализация Стрибога и Кузнечика

Реализация хэш-функции «Стрибог» (ГОСТ 34.11-2018) и блочного шифра
«Кузнечик» (ГОСТ 34.12-2018) на чистом Python, без сторонних
криптографических библиотек. Эти примитивы используются во всех трёх
вариантах задания, поэтому реализованы первыми и отдельно от них.

## Структура

- `sbox.py` — подстановка π и обратная к ней π⁻¹; таблица общая для обоих
  стандартов
- `streebog.py` — Стрибог: преобразования X, S, P, L, функция сжатия g_N,
  процедура вычисления хэш-кода; `streebog256()` и `streebog512()`
- `kuznechik.py` — Кузнечик: арифметика поля Q, преобразования S, R, L и
  обратные к ним, развёртывание ключа, класс `Kuznechik` с методами
  `encrypt()` и `decrypt()` для одного блока
- `tests/` — проверка по всем контрольным примерам стандартов, включая
  промежуточные значения

## Запуск тестов

```bash
pip install -r requirements.txt
python -m pytest tests/
```

Если дополнительно установлен пакет `gostcrypto`, запускаются ещё и
сверочные тесты на случайных данных: хэш на 10 длинах сообщений от 0 до 200 байт
(в том числе на границах блока: 63/64/65 и 127/128/129 байт) и шифрование на случайных
ключах. Без пакета эти тесты пропускаются, а сама реализация от него не
зависит.

## Порядок байтов

Стандарты записывают векторы шестнадцатеричным числом, старший байт слева.
Для байтовых строк используются те же соглашения, что в RFC и в
распространённых реализациях:

| | Байтовая строка ↔ запись в стандарте |
|---|---|
| Стрибог | первый байт строки — младший байт вектора, поэтому значения из стандарта читаются задом наперёд. Например, сообщение M1 в стандарте записано как `3231...3130`, а байтовая строка — это `"0123...012"` |
| Кузнечик | порядок совпадает: `bytes.fromhex(запись из стандарта)` |

## Контрольные примеры

| Пример | Что проверяется | Результат |
|---|---|---|
| Стрибог, пример 1 (63 байта), 512 и 256 бит | дополнение блока, S, P, L, первая итерационная константа, g_N, итоговый хэш-код | PASS |
| Стрибог, пример 2 (72 байта, текст в CP1251), 512 и 256 бит | обработка полного блока (этап 2), g_N по каждому блоку, N и Σ, итоговый хэш-код | PASS |
| Кузнечик, преобразования S, R, L | по 4 последовательных значения для каждого, S и L проверяются ещё и в обратную сторону | PASS |
| Кузнечик, развёртывание ключа | константы C₁…C₈, раундовые ключи K₁…K₁₀ | PASS |
| Кузнечик, зашифрование | состояние после каждого из 9 раундов, итоговый шифртекст | PASS |
| Кузнечик, расшифрование | состояние после каждого из 9 раундов, итоговый открытый текст | PASS |

## Источники констант и примеров

Тексты алгоритмов в ГОСТ 34.11-2018 и ГОСТ 34.12-2018 совпадают с
ГОСТ Р 34.11-2012 и ГОСТ Р 34.12-2015, официальные переводы которых
опубликованы как RFC 6986 и RFC 7801. Константы (π, τ, матрица A,
C₁…C₁₂) извлечены из текста RFC программно, а не перепечатаны вручную,
и перекрёстно проверены: таблицы π в обоих RFC совпадают, π⁻¹,
вычисленная из π, совпадает с таблицей RFC 7801, τ — транспонирование
матрицы байтов 8×8.

| Элемент | RFC 6986 (Стрибог) | RFC 7801 (Кузнечик) |
|---|---|---|
| π | §6.2 | §4.1 |
| τ, A, C₁…C₁₂ | §6.3–6.5 | — |
| ℓ, поле Q | — | §3.2, §4.2 |
| Преобразования | §7 | §4.3 |
| g_N, E | §8 | — |
| Развёртывание ключа | — | §4.4 |
| Процедура хэширования / шифрования | §9 | §4.5 |
| Контрольные примеры | §10 | §5 |

## Замечания к источникам

В тексте RFC 7801 две опечатки, которых нет в контрольных примерах. Если
реализовать формулы буквально, контрольный пример не сходится (проверено):

1. **§4.2, формула ℓ.** Второе слагаемое записано как `32*delta(a_15)`,
   хотя должно быть `32*delta(a_14)`: переменная a_15 встречается дважды,
   a_14 не встречается вовсе. Реализация использует a_14.
2. **§4.5.2, формула расшифрования.** Записано
   `X[K_1]L^(-1)S^(-1)X[K_2]...`. По соглашению из §3.2 правое
   преобразование выполняется первым, то есть получается сначала S⁻¹,
   потом L⁻¹. Но обратным к LSX[k] является X[k]S⁻¹L⁻¹, где первым
   выполняется L⁻¹, и в контрольном примере §5.6 порядок именно такой.
   Реализация следует контрольному примеру.

Если опечатки есть и в бумажном тексте ГОСТ, их стоит указать в анализе
качества документа.
