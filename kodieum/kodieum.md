# Декомпозиция алгоритма «Кодиеум» на составляющие

Настоящий раздел выделяет из текста проекта методических рекомендаций
алгоритмы, подлежащие программной реализации, и указывает их входные/
выходные данные и последовательность выполнения.

«Кодиеум» — постквантовый **механизм инкапсуляции ключа** на основе
кодов, исправляющих ошибки (теоретико-кодовая схема типа Classic
McEliece/Нидеррайтер). Стойкость основана на задаче синдромного
декодирования.

## 1. Математический фундамент (раздел 5.3 МР)

Арифметика в конечном поле F₂ᵐ: сложение (XOR), умножение через LFSR-сдвиг
(`fshift`), обратный элемент по теореме Ферма. Используется всеми
остальными алгоритмами.

## 2. Внешние криптопримитивы

Схема опирается на три криптографических примитива, которые сама не
определяет, а ссылается на действующие стандарты: хэш-функция Стрибог-256
(ГОСТ 34.11-2018), блочный шифр Кузнечик (ГОСТ 34.12-2018) и функция
деривации ключа KDF_TREE_GOSTR3411_2012_256 (Р 50.1.113-2016). Документ
использует их как готовые строительные блоки, а в проекте все три
реализованы самостоятельно в каталоге `gost/`.

## 3. Вспомогательные алгоритмы (раздел 6 МР)

| Алгоритм | Назначение | Вход | Выход |
|---|---|---|---|
| `gen_unique_seq` | получить n попарно различных чисел в диапазоне [0, 2ᵐ) | m, n, 256-битный ключ | список из n чисел |
| `gen_weight_vec` | получить псевдослучайный двоичный вектор заданной длины с заданным числом единиц | n, t, m, 256-битный seed | двоичный вектор длины n, вес t |
| `Decode` | по синдрому восстановить вектор ошибки (декодирование кода Гоппы, модифицированный алгоритм Берлекэмпа–Мэсси) | опорные точки a, g, синдром s | вектор ошибки веса t либо символ отказа ⊥ |

Внутри `Decode` отдельно выделяется подзадача — решение однородной системы
линейных уравнений над F₂ᵐ.

## 4. Три основных процесса (раздел 8 МР)

Образуют протокол формирования общего ключа между двумя сторонами.

### 4.1 Генерация ключевой пары (KeyGen, раздел 8.1)

**Вход:** параметры схемы (n, m, t) и примитивный многочлен поля.
**Выход:** ключ инкапсуляции pk (открытый) и ключ декапсуляции sk
(закрытый).

Последовательность: из случайного 256-битного seed вырабатываются через
KDF два вспомогательных seed и маскирующий вектор salt; на их основе
`gen_unique_seq` строит опорные точки для кода Гоппы; из них строится
проверочная матрица кода; матрица приводится к систематическому виду. Если
привести не удаётся, процесс повторяется с новым seed. Это обычный путь, а
не аварийный: на secparam1264 неудачными оказались 45 попыток из 60, то
есть в среднем нужно около четырёх попыток.

### 4.2 Инкапсуляция ключа (Encaps, раздел 8.2)

**Вход:** ключ инкапсуляции pk (принадлежит получателю).
**Выход:** общий секретный ключ shk (256 бит) и шифртекст enk, который
отправляется получателю по открытому каналу.

Последовательность: генерируется случайный вектор ошибки заданного веса;
по нему и открытому ключу вычисляется синдром — это и есть шифртекст;
общий ключ вычисляется хэшированием вектора ошибки вместе с синдромом.

### 4.3 Декапсуляция ключа (Decaps, раздел 8.3)

**Вход:** ключ декапсуляции sk (свой закрытый ключ) и полученный от
отправителя шифртекст enk.
**Выход:** тот же общий секретный ключ shk, что был вычислен отправителем
в п. 4.2.

Последовательность: из закрытого ключа восстанавливаются те же опорные
точки, что использовались при генерации ключевой пары; к ним и к
полученному синдрому применяется `Decode`. При успешном декодировании
общий ключ вычисляется так же, как на стороне отправителя. При неудаче
(например, повреждённый шифртекст) вместо вектора ошибки используется
маскирующий вектор salt: результат выглядит как обычный ключ, и отказ
декодирования не виден по ответу (неявный отказ). От анализа времени
выполнения это само по себе не защищает.

### 4.4 Варианты процессов (разделы 7, 8.1.1, 8.3.1 МР)

Документ разрешает («можно») три изменения основного режима:

- **KeyGen2 / Decaps2.** В ключ декапсуляции кладётся сама
  последовательность ℓ вместо seed₂: sk = (ℓ, salt). Decaps2 выполняет
  шаги 2–7 Decaps, не вырабатывая ℓ заново.
- **Без согласования параметров.** pk = (A, t), sk = (seed₂, salt, p) или
  (ℓ, salt, p). Encaps вычисляет k — число столбцов A, n = r + k и
  m = r/t, а Decaps — n по длине salt, m по длине p и t = r/m.
- **«Стрибог-512» вместо H₂₅₆** при выработке shk.

## 5. Параметры и ограничения

| Параметр | Смысл | Ограничение | Откуда |
|---|---|---|---|
| n | длина кода | m·t < n | раздел 7 |
| m | степень поля F₂ᵐ | m ⩽ 16 | неявно, 6.2 шаг 3: bᵢ берётся из 16-битного слова |
| t | число исправляемых ошибок | n + t < 2ᵐ | неявно, 6.1 вызывается с n + t |
| p | вектор (p₀, …, p_{m−2}) примитивного многочлена | длина m − 1, многочлен примитивный | разделы 3.2, 5.3 |
| seed₁, seed₃ | случайные векторы | 256 бит | раздел 7 |
| seed₂, seed′ | псевдослучайные векторы | 256 бит | 8.1 шаг 2 |
| salt | маска для отказа | n бит | 8.1 шаг 2 |

Наборы параметров — таблица 2 приложения А: secparam1264, secparam1396,
secparam14128. Неявные ограничения m ⩽ 16 и n + t < 2ᵐ в разделе 7 не
названы (см. `ANALYSIS.md`, предложение 7).

## 6. Специальные и граничные случаи

- **KeyGen, шаг 7.** Если H не приводится к виду (I_mt ‖ A), шаги
  повторяются с seed₁ = seed′. На secparam1264 так бывает примерно в трёх
  попытках из четырёх.
- **gen_weight_vec, шаги 4–5.** Если среди ℓ·t значений меньше t чисел,
  меньших n, или среди первых t есть повторы, выработка повторяется с
  seed′. При t, сравнимом с n, алгоритм практически не завершается.
- **Decode, шаг 18 и 26.** Отказ ⊥, если y_t = 0 или у локатора не ровно
  t корней. Отдельно: Decode не проверяет, что синдром найденного e
  равен s (`ANALYSIS.md`, предложение 3).
- **Decaps, шаг 5.** При отказе shk = H₂₅₆(salt ‖ s); снаружи это
  неотличимо от успешной декапсуляции.
- **Нулевой синдром** s = 0 соответствует только нулевому вектору ошибок,
  поэтому Decaps возвращает H₂₅₆(salt ‖ s).

## 7. Представление данных

- Двоичный вектор ↔ число по формуле (5.1): a = Σ aᵢ·2ⁱ.
- Элемент F₂ᵐ — число от 0 до 2ᵐ − 1, бит i — коэффициент при xⁱ.
- Матрица H составляется из блоков Hᵢ, в которых элемент hᵢ,ⱼ записан
  столбцом из m бит (8.1 шаги 6.6–6.7).
- Сериализация векторов и матриц в байты и шестнадцатеричная запись
  примеров описаны только в справочном приложении Б.1. Как байты подаются
  в «Стрибог», «Кузнечик» и KDF, в документе не сказано: соглашения
  восстановлены по примерам (`README.md`, `ANALYSIS.md`, предложение 1).
- Форматы ключей и шифртекста в байтах не определены (`ANALYSIS.md`,
  предложение 8).

## 8. Обработка ошибочных входных данных

Документ определяет только неявный отказ в Decaps. Что делать при входе
неверной длины или при неверных параметрах, не сказано. Реализация
отвергает такие входы с `ValueError`: шифртекст длиннее mt бит, ключ
инкапсуляции не размера mt × (n − mt), ℓ не из n + t элементов, длины в
режиме без согласования, при которых r не делится на t или на m, и
параметры, нарушающие ограничения из раздела 5 выше.
