# Декомпозиция алгоритма «Кодиеум» на составляющие

Настоящий раздел выделяет из текста проекта методических рекомендаций
алгоритмы, подлежащие программной реализации, и указывает их входные/
выходные данные и последовательность выполнения.

«Кодиеум» — постквантовый **механизм инкапсуляции ключа** на основе
кодов, исправляющих ошибки (теоретико-кодовая схема типа Classic
McEliece/Нидеррайтер). Стойкость основана на задаче синдромного
декодирования.

## 1. Математический фундамент (раздел 5.3 МР)

Арифметика в конечном поле F₂ᵐ: сложение (XOR), умножение через LFSR-сдвиг
(`fshift`), обратный элемент по теореме Ферма. Используется всеми
остальными алгоритмами.

## 2. Внешние криптопримитивы

Схема опирается на три криптографических примитива, которые сама не
определяет, а ссылается на действующие стандарты: хэш-функция Стрибог-256
(ГОСТ 34.11-2018), блочный шифр Кузнечик (ГОСТ 34.12-2018) и функция
деривации ключа KDF_TREE_GOSTR3411_2012_256 (Р 50.1.113-2016). Эти три
примитива не являются предметом реализации по заданию — документ
использует их как готовые строительные блоки.

## 3. Вспомогательные алгоритмы (раздел 6 МР)

| Алгоритм | Назначение | Вход | Выход |
|---|---|---|---|
| `gen_unique_seq` | получить n попарно различных чисел в диапазоне [0, 2ᵐ) | m, n, 256-битный ключ | список из n чисел |
| `gen_weight_vec` | получить псевдослучайный двоичный вектор заданной длины с заданным числом единиц | n, t, m, 256-битный seed | двоичный вектор длины n, вес t |
| `Decode` | по синдрому восстановить вектор ошибки (декодирование кода Гоппы, модифицированный алгоритм Берлекэмпа–Мэсси) | опорные точки a, g, синдром s | вектор ошибки веса t либо символ отказа ⊥ |

Внутри `Decode` отдельно выделяется подзадача — решение однородной системы
линейных уравнений над F₂ᵐ.

## 4. Три основных процесса (раздел 8 МР)

Образуют протокол формирования общего ключа между двумя сторонами.

### 4.1 Генерация ключевой пары (KeyGen, раздел 8.1)

**Вход:** параметры схемы (n, m, t) и примитивный многочлен поля.
**Выход:** ключ инкапсуляции pk (открытый) и ключ декапсуляции sk
(закрытый).

Последовательность: из случайного 256-битного seed вырабатываются через
KDF два вспомогательных seed и маскирующий вектор salt; на их основе
`gen_unique_seq` строит опорные точки для кода Гоппы; из них строится
проверочная матрица кода; матрица приводится к систематическому виду. Если
привести не удаётся (вероятность мала, но не нулевая), процесс повторяется
с новым seed — это предусмотренный документом, а не аварийный путь.

### 4.2 Инкапсуляция ключа (Encaps, раздел 8.2)

**Вход:** ключ инкапсуляции pk (принадлежит получателю).
**Выход:** общий секретный ключ shk (256 бит) и шифртекст enk, который
отправляется получателю по открытому каналу.

Последовательность: генерируется случайный вектор ошибки заданного веса;
по нему и открытому ключу вычисляется синдром — это и есть шифртекст;
общий ключ вычисляется хэшированием вектора ошибки вместе с синдромом.

### 4.3 Декапсуляция ключа (Decaps, раздел 8.3)

**Вход:** ключ декапсуляции sk (свой закрытый ключ) и полученный от
отправителя шифртекст enk.
**Выход:** тот же общий секретный ключ shk, что был вычислен отправителем
в п. 4.2.

Последовательность: из закрытого ключа восстанавливаются те же опорные
точки, что использовались при генерации ключевой пары; к ним и к
полученному синдрому применяется `Decode`. При успешном декодировании
общий ключ вычисляется так же, как на стороне отправителя. При неудаче
(например, повреждённый шифртекст) вместо вектора ошибки используется
маскирующий вектор salt — это предотвращает раскрытие информации через
различие во времени выполнения между успешным и неуспешным случаем.
